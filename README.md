## 摘要

本作品基于安路 PH1P35MDG324 FPGA，构建了一套全程无 CPU、无软件算法参与的纯硬件实时视觉预处理系统。系统以 MIPI 摄像头的 RAW10 原始数据为输入，在片内以流水线方式完成图像信号处理与视觉算法，最终经 HDMI 实时输出，并叠加中文算法状态、毫秒级处理延迟等可视化信息。

图像质量方面，本方案在参考例程仅做去马赛克与白平衡的基础上，补齐了**四通道黑电平校正（BLC）**、**Gamma 校正**与**色彩增强**三级处理，并针对画质缺陷的成因逐项定位与取舍。算法方面，本方案以**逐帧亮度统计闭环驱动数字自动增益**：画面过亮时自动压暗、过暗时自动提亮，并以死区抑制收敛震荡，使系统在强光、暗光等复杂光照场景下保持稳定可视。

运动检测采用**分块均值帧差法**，并针对真实摄像头场景中自动曝光/自动白平衡引起的整体亮度漂移，设计了**全局光照突变抑制**机制，有效区分"物体运动"与"光照变化"，解决了传统帧差法在自动曝光环境下全屏误报的问题。检测到运动目标时，系统通过 LED 与蜂鸣器同步报警。

工程实现方面，本系统历时多轮时序迭代，将最差建立时间从 **-6.315 ns 收敛至 +0.104 ns**，最终 LUT 占用 78.2%、ERAM 占用 49%、DSP 占用 25%，全设计 0 时序违例，并已固化至板载 QSPI Flash，上电即可独立运行，无需 PC 干预。

**关键词**：FPGA；硬件流水线；自适应 ISP；大津法；运动目标检测；低延迟

## 第一部分  作品概述

### 1.1 功能与特性

系统支持五种工作模式，通过三路拨码开关一键切换，切换结果实时显示于画面：

| 拨码组合 | 模式 | 画面内容 |
|---|---|---|
| 全不拨 | 模式一 | 彩色原图（经 BLC、Gamma、色彩增强处理） |
| SW1 | 模式二 | Scharr 边缘检测（固定阈值） |
| SW2 | 模式三 | 灰度化 |
| SW1+SW2 | 模式四 | 运动目标检测与报警 |
| SW3 | 模式五 | 自适应图像（数字自动增益闭环） |

系统同时具备：毫秒级处理延迟的屏幕量化显示、运动目标出现时 LED 与蜂鸣器同步报警、中文算法状态叠加。全部功能集成于单一镜像，上电自动运行。

### 1.2 应用领域

本系统面向对**实时性与确定性**要求苛刻的嵌入式视觉场景：

- **工业视觉检测**：产线边缘提取、缺陷轮廓识别。纯硬件流水线延迟固定且极低，适合与运动机构闭环配合。
- **周界与危险区域防护**：以视觉替代传统安全光幕，可覆盖平面区域而非单条线，本方案的运动检测与报警输出可直接驱动警示设备。
- **视频监控与低照度增强**：Gamma 与色彩增强可改善弱光画面的可视性。
- **教学与科研平台**：完整的 ISP 流水线实现，可作为数字图像处理与 FPGA 设计的综合实践载体。

### 1.3 主要技术特点

**（1）纯硬件流水线，零软件参与。** 从 MIPI 采集到 HDMI 输出全部由 Verilog 时序逻辑实现，无处理器、无 RTOS、无 PC 参与，处理延迟固定可预测。

**（2）补齐了参考例程缺失的画质环节。** 原厂例程仅实现去马赛克与白平衡，本方案补充了**四通道黑电平校正**（原厂提供模块但未例化）、**Gamma 校正**与**色彩增强**，显著改善暗部发灰与色彩寡淡问题。

**（3）以亮度统计闭环实现环境自适应。** 硬件逐帧统计全画面亮度均值，与目标亮度区间比较后调整数字增益档位，过亮自动压暗、过暗自动提亮；区间内设置死区，避免在目标点附近来回震荡，收敛平稳。

**（4）针对自动曝光环境的运动检测。** 采用分块均值帧差并引入全局光照突变抑制，解决了自动曝光/白平衡漂移导致的全屏误报。

**（5）显示域算法状态叠加。** 中文模式文字与延迟数据在显示时钟域绘制，位置严格锁定于视频时序，不随 MIPI 接收端相位抖动。

### 1.4 主要性能指标

| 指标 | 数值 |
|---|---|
| 视频分辨率 / 帧率 | 1280 × 720 @ 60 fps |
| 摄像头接口 | MIPI CSI-2，2-lane，RAW10 |
| 显示接口 | HDMI（TMDS） |
| 单帧处理延迟 | 约 17 ~ 34 ms（受帧缓存约束） |
| LUT 占用 | 16,583 / 21,216（78.2%） |
| ERAM 占用 | 53 / 108（49.1%） |
| DSP 占用 | 10 / 40（25.0%） |
| 最差建立时间（slow corner） | +0.104 ns（0 违例） |
| 最终综合时钟 | MIPI_RX_BYTE_CLK，9.660 ns |
| 上电启动 | QSPI Flash 固化，无需 PC |

### 1.5 主要创新点

1. **逐帧亮度统计闭环驱动数字自动增益**：全部以移位加法实现（0.75×/1×/1.25×/1.5×），无乘法器；配合死区判据，既实现环境自适应又抑制了收敛震荡。
2. **全局光照突变抑制**：以"变化块占比超过半数即判定为光照变化"的判据，从原理上区分物体运动与自动曝光漂移。
3. **显示域绘制算法状态**：解决了在 ISP 域绘图导致的文字随帧起始相位抖动问题，并给出可复现的定位过程。
4. **完整的时序收敛工程方法**：六次违例定位、四类典型故障（组合路径过长、布线拥塞、位宽截断、加法链不自动平衡）的系统性排查与修复。
5. **画质缺陷的量化取舍**：明确识别镜头色彩阴影与色彩增强放大效应，并以饱和度上限约束二者矛盾。

### 1.6 设计流程

系统设计遵循"基线复现 → 逐级增强 → 仿真验证 → 上板迭代"的流程：

1. 以官方 SC520 参考工程（MIPI + ISP + DDR + HDMI）为基线，确认采集与显示链路稳定；
2. 依次接入统计与 Otsu、边缘检测、二值化、运动检测、色彩增强等模块，每级均先通过 ModelSim 仿真验证；
3. 每轮改动后重新综合，读取 `final_timing.rpt` 中的最差路径，定位并修复时序违例；
4. 功能与性能达标后固化至 QSPI Flash，验证上电自启动。

## 第二部分  系统组成及功能说明

### 2.1 整体介绍

系统数据流如下（→ 表示硬件流水线级）：

```
MIPI 摄像头 SC520CS (2-lane RAW10)
        │
        ▼
  MIPI D-PHY RX ── CSI 解包 ── RAW10 解包
        │
        ▼
  四通道黑电平校正 BLC  ← 本方案新增（原厂模块未例化）
        │
        ▼
  Bayer 插值 Demosaic（BGGR）
        │
        ▼
  自动白平衡 AWB（原厂）
        │
        ▼
  ┌─────────────────────────────────────────────┐
  │  vis_top 视觉处理链（本方案自建）               │
  │   Gamma 校正 → 色彩增强 → 模式分支              │
  │     模式一：直通（增强彩色图）                  │
  │     模式二：Scharr 边缘检测（固定阈值）         │
  │     模式三：灰度化                             │
  │     模式四：直通 + 运动检测报警                 │
  │     模式五：数字自动增益（亮度统计闭环）         │
  │   同时运行：逐帧亮度统计（供自动增益闭环使用）   │
  │   同时运行：分块均值帧差运动检测                │
  └─────────────────────────────────────────────┘
        │
        ▼
  96bit → 128bit 位宽转换 → DDR2 帧缓存
        │
        ▼
  显示时序生成 uivtc → 显示域 OSD 叠加 → HDMI TX
        │
        ▼
     显示器（画面 + 中文模式 + 延迟毫秒数）
```

各模块关系说明：采集与 ISP 链路工作在 MIPI 接收时钟域，帧缓存完成跨时钟域解耦，显示链路工作在 HDMI 像素时钟域（75 MHz）。模式选择信号由拨码开关经消抖后产生于 ISP 时钟域，经两级触发器同步后送往显示域，用于选择 OSD 文字。统计与 Otsu 引擎与视频通路并行运行，仅在行消隐期占用资源，不引入额外像素延迟。

### 2.2 硬件系统介绍

#### 2.2.1 硬件整体介绍

- **主控**：安路 PH1P35MDG324（LUT 38,184 / DFF 42,432 / ERAM 2,160 Kbit / DSP 40 / PLL 6），板载于 HX1P35A 开发板。
- **图像输入**：Smartsens SC520CS，500 万像素，2-lane MIPI，输出 RAW10。
- **帧缓存**：板载 DDR2，用于解耦采集与显示时钟域。
- **显示输出**：HDMI 1.4b（TMDS）。
- **人机交互**：三路拨码开关（模式选择）、四路 LED、蜂鸣器（经三极管驱动，低电平有效）。

#### 2.2.2 电路各模块介绍

本方案未改动板卡硬件电路，全部功能由 FPGA 内部逻辑实现。新增的 FPGA 引脚约束如下：

| 信号 | 引脚 | 说明 |
|---|---|---|
| `I_key_sw1` | A4 | 模式选择（输入） |
| `I_key_sw2` | B4 | 模式选择（输入） |
| `I_key_sw3` | E11 | 模式五选择（输入） |
| `O_led[3:0]` | D10 / E10 / C6 / D6 | 报警指示（输出） |
| `O_buzzer` | C12 | 蜂鸣器（低电平有效，经三极管） |

### 2.3 软件系统介绍

**本系统不包含任何 PC 端或云端软件，也不包含嵌入式处理器上运行的软件。**

这是本方案的核心特征：全部算法由 Verilog 硬件描述语言实现，综合为纯组合逻辑与时序逻辑。系统上电后自动从 QSPI Flash 加载配置并运行，全程无需主机干预，亦不存在操作系统、驱动程序或调度延迟。

各硬件模块的设计说明（从顶层到底层）：

| 模块 | 功能 | 关键接口 |
|---|---|---|
| `isp_top` | ISP 顶层，集成 BLC、Demosaic、AWB 与视觉处理链 | 40bit RAW10 输入 / 128bit RGB 输出 |
| `vis_frame_stats` | 逐帧 64 档亮度直方图与 RGB 统计，双缓冲乒乓存储 | `I_tdata[95:0]` → 直方图读口 |

| `vis_auto_gain` | 数字自动增益，亮度闭环 + 死区 | 96bit RGB + 亮度和 → 96bit RGB |
| `vis_color_enh` | Gamma 校正 + 色度增强，两级流水 | 96bit RGB → 96bit RGB |
| `vis_motion_grid` | 分块均值帧差运动检测 + 光照突变抑制 | 96bit RGB → 外框坐标与计数 |
| `vis_text_osd_disp` | 显示域中文状态与延迟叠加 | 24bit RGB + 时序 → 24bit RGB |
| `vis_top` | 模式选择与流水线整合 | 96bit 输入 / 96bit 输出 |

## 第四部分  总结

### 4.1 可扩展之处

本方案已实现完整的采集、ISP、视觉算法与显示链路。以下环节为完整的工业 ISP 应有而本版未纳入的部分，其取舍原因一并说明：

| 环节 | 作用 | 未纳入原因 |
|---|---|---|
| **LSC 镜头阴影校正** | 补偿镜头径向亮度衰减与 R/G/B 衰减不一致 | 需 32×32×3 通道增益表与双线性插值，约 800~1200 LUT。当前 LUT 占用 78.2%，无余量 |
| **CCM 色彩校正矩阵** | 将传感器原生色域映射至标准 sRGB | 每拍需 36 次乘法（4 像素 × 9 系数），DSP 资源虽有余量，但乘法路径引入新关键路径的概率极高 |
| **分区自动白平衡** | 解决混合光源下全局白平衡顾此失彼的问题 | 需分区统计与加权融合，约 1,500 LUT |
| **自适应降噪** | 平坦区高斯滤波、边缘区中值滤波平滑切换 | 需行缓冲与排序网络，约 1,000 LUT |
| **CLAHE 限制对比度自适应直方图均衡** | 分块直方图均衡，提升局部对比度 | 需分块直方图、限幅重分配与双线性插值，约 2,000 LUT 及大量 BRAM，超出器件容量 |

经实测，画面存在从中心向四周的色彩渐变，判断为镜头色彩阴影。完整补偿需上述 LSC，本版已通过全局色度修正部分补偿，并在色彩增强环节将饱和度增益限制在 1.25 倍，以抑制该缺陷被同步放大。

### 4.2 心得体会

回顾整个研发过程，最深的体会是：**在真实的硬件系统里，"能不能做"往往不是问题，"装不装得下、跑不跑得快"才是。**

项目初期，我们的方案书里罗列了一长串算法名称。真正动手后才发现两件事。第一，官方参考例程已经实现了其中的自动白平衡、曝光配置与 OSD 叠加，把这些当作创新点是不成立的；第二，像素并行意味着每增加一级运算，代价要乘以每拍的像素数——每拍 4 个像素、每个像素 3 个通道，一个看似简单的"每像素一次乘法"在硬件里就是每拍 12 个乘法器。

整个项目最耗时的部分不是写算法，而是**与时序搏斗**。我们先后六次遭遇建立时间违例，最差达到 -6.315 ns。前四次全部定位在同一个模块、同一个病根：**组合路径上串了乘法与加法**。Verilog 的加法是左结合的，`a+b+c+d` 综合出来就是一条串行加法链，工具不会自动帮你平衡；而把乘法结果寄存、把加法独立成拍之后，最差路径立刻从 -6.315 ns 收敛到 +0.114 ns，且 LUT 减少了 621 个——长组合路径消失后，综合器不再需要复制逻辑去抢时间。

还有一次教训更为深刻：加上 Gamma 查表后，余量从 +0.101 ns 骤降至 +0.009 ns。我们最初试图通过手工平衡加法树来修复，结果只回收了 0.005 ns，几乎无效。直到重新阅读时序报告，才注意到 `net delay` 占了路径延迟的 41%——**瓶颈不是逻辑级数，而是布局拥塞**：LUT 占用已达 76%，工具没有空间就近摆放，信号被迫在芯片上绕远路。最终的解法是切断路径、插入流水级，而不是继续优化逻辑结构。这件事让我明白：**读时序报告要读到底，而不是只看 slack 数字。**

另有一类故障特别隐蔽：**位宽截断**。我们在项目中四次踩到同一个坑——`3'd8` 因为 8 需要 4 位而被截断成 0，导致位置比较恒为假、模式文字完全不显示；`pos` 计数器只有 3 位却要寻址 12 个字符位；模式同步器是 2 位却要传递 5 个模式值；字模索引移位后映射表未同步更新。这类错误**不报错、不中断，只给一条容易忽略的警告**，最终表现为"逻辑明明对但就是不工作"。

算法层面最有价值的发现，是**自动曝光与帧差法运动检测之间的根本矛盾**。方案书里把 AE/AWB 当作卖点，但它们恰恰是运动检测最大的干扰源：传感器与白平衡持续微调，画面整体亮度缓慢漂移，帧差法会把整幅画面判为"运动"，外框覆盖全屏、报警常亮。我们最终的解法是引入**全局光照突变抑制**——当一帧内变化的块数超过总数的一半时，判定为光照变化而非物体运动。这个判据简单、几乎不耗资源，却从原理上区分了两类变化。这也让我意识到：**真正有工程价值的创新，往往不是更复杂的算法，而是对问题机理的准确把握。**

最后是关于取舍。随着功能叠加，器件资源逼近上限，我们不得不在多个候选模块之间做选择。最终砍掉了已经调试通过的 USM 锐化——不是因为它不好，而是因为它恰好落在关键路径上，而它带来的收益（边缘更锐）远小于时序不收敛的风险。**在工程项目里，"知道什么该不做"和"知道什么该做"同样重要。**
